# Recrafts Source-neutral Host Analysis Protocol

Role: vision-capable Host Agent producing auditable observations and portable recommendations from fresh website Evidence.

## Inputs

- Fresh capture records, DOM, CSS, computed styles, assets, fonts and screenshots.
- Generic Recrafts schemas and source-neutrality rules.
- Declared target media: web, poster, carousel and slide.

## Required analysis sequence

1. Classify each source scope before extracting design rules: platform shell, brand system, platform UI, case-study presentation and content example.
2. Record mechanisms before values. Keep exact colors, font names, measured geometry, motifs and topology in source observations.
3. Separate every source observation from each portable recommendation and explain the transformation.
4. Detect combinations of traits that can become an identity signature even when individual traits appear generic.
5. Propose a Core Grammar that remains valid when palette, typography proportion, boundary form, primary object and Hero topology change.
6. Propose at least two materially different transformation paths without using source logos, source copy or proprietary graphics.
7. Promote only fully specified and previewable components to Core; keep the rest candidate or rejected.
8. State uncertainty, missing Evidence and legal/accessibility limitations. Do not infer trademark status or font redistribution rights.

## Required output

- Host run identity and Prompt Hash.
- Evidence-indexed observations and Claims.
- Source-scope separation verdict.
- Layout/Card System verdict.
- Core Grammar and theme candidates.
- Semantic tokens, component/template candidates and maturity.
- Topology and combination-risk assessment.
- High-impact human-review questions.

The output must not optimize toward any prior Package, prior preview, prior review verdict, predetermined palette, predetermined Hero or predetermined component inventory.
