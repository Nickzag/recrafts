# R-009A 中文可视化评分表设计

## 目标

将 R-009A 人工评分审阅入口完整中文化，并提供一个独立、可交互的评分页面。页面必须把每项需要评价的原始画面、候选提取结果和评分控件放在同一张审阅卡内，让项目所有者不依赖外部编号或跨页面查找即可理解评分对象。页面生成符合 `validate-human-score.mjs` 输入约束的 JSON，并通过浏览器剪贴板复制；不得代填评分、自动写入仓库、执行修正或改变候选包。

## 文件边界

- 保留 `benchmarks/L2-brand/static-coffee/reviews/r009a/human-score-form.md`，改为中文静态审计表。
- 新增 `benchmarks/L2-brand/static-coffee/reviews/r009a/human-score-form.html`，作为独立交互页面。
- 更新 `scripts/benchmarks/generate-r009a-review-workspace.mjs`，确保新生成的工作区包含中文 Markdown、交互页面及统一导航入口。
- 更新现有四个审阅 HTML 的导航与首页行动入口，不改变 Source、Evidence、Claim 或 Candidate Artifact 内容。

## 界面结构

页面沿用现有 R-009A 审阅工作区的视觉语言，包含：

1. 固定审阅身份：Nick / 项目所有者。
2. 审阅元数据：日期、语料集、来源包、候选运行、审阅环境。
3. 两个确认项：来源包哈希已验证、修正提案已审阅。
4. 八个评分卡：中文模块名称、稳定 ID、评价对象说明、对应原始画面、候选提取结果、观察重点、1–5 单选评分、评分理由和折叠的可选技术引用。
5. 中等影响冲突决定：确认、修订或拒绝，以及决定理由。
6. 完整性状态：显示已完成模块数与缺失字段。
7. JSON 预览和“一键复制 JSON”按钮。

评分含义统一为：

- 1：严重不足
- 2：明显不足
- 3：基本可用
- 4：良好
- 5：优秀

每张评分卡按以下顺序组织：

1. “你正在评价什么”：用中文解释本项对应的系统能力和判断边界。
2. “对应画面”：展示与本项直接相关的 4–8 张 Source 图片，并标注对应的中文观察重点。
3. “候选提取结果”：从 Candidate Package 中选择与本项相关的 Token、Claim、Region、组件或语法，以中文摘要呈现；没有结果时明确显示“当前未提取到内容”，不得用空白掩盖 Runtime 限制。
4. “如何评分”：显示 1、3、5 分的具体中文锚点，2 和 4 分表示相邻锚点之间的程度。
5. 评分控件和必填的中文评分理由。
6. 默认折叠的“可选：技术引用”，包含 Artifact refs 和 Evidence refs。

评分模块与画面/候选结果的关联由生成器中的显式配置维护，不根据文件名或页面顺序临时猜测。至少覆盖字体、色彩、包装、编辑排版、标牌、摄影、跨应用一致性、案例展示和 Scope/Intent 纪律。整体实用性评分使用一组具有代表性的跨类型画面和候选结果摘要。

除稳定机器标识和原始 JSON 值外，所有需要项目所有者阅读、判断或操作的标题、导航、按钮、字段名、状态、提示和错误信息均使用中文。必要的英文稳定值必须同时提供中文解释，不得单独作为操作文案。

## 数据结构与交互

浏览器只在内存中维护表单状态。点击“生成并复制 JSON”时：

1. 验证八个模块均选择 1–5 整数分。
2. 验证每项存在非空评分理由；Artifact refs 和 Evidence refs 均为可选。
3. 对已填写的引用，将逗号或换行分隔的内容规范化为字符串数组并去重；留空时输出空数组。
4. 仅在引用已填写时验证：Artifact ref 必须是安全的相对文件引用，Evidence ref 必须以 `ev-` 开头。
5. 验证审阅日期和两个确认项已完成。
6. 生成 `status: complete`、Reviewer/Corpus/Source Pack/candidate run 元数据及八项 `scores` 的 JSON。
7. 将 JSON 显示在页面中，并调用 Clipboard API 复制；若剪贴板不可用，保留可手动复制的预览和明确提示。

页面不使用网络请求、Local Storage、文件下载或自动文件写入。Correction 决定只进入生成结果的 review context，不触发任何 Runtime Operation。

## 错误处理

- 未完成时，按钮保持可点击以便执行校验，但不得生成 `complete` JSON；页面将聚焦第一个错误并列出缺失项。
- 可选引用留空不构成错误；已填写但无效的引用显示在所属评分卡内，不静默删除。
- Clipboard API 失败时显示“请从预览区手动复制”，不丢失已输入内容。
- 页面刷新会清空未复制内容，并在页首明确提示该行为。

## 验证

- 单元测试确认生成器包含中文标题、八个稳定模块 ID、五档评分、每项对应画面、候选结果摘要、观察重点和 JSON 生成逻辑。
- 单元测试确认 Artifact refs 与 Evidence refs 可留空；填写时仍执行引用安全校验。
- 单元测试确认页面中所有面向项目所有者的操作和理解文案均为中文，并拒绝新的未解释英文操作标签。
- 单元测试确认生成结构可被 `validateHumanScore` 接受，并拒绝漏分、空理由和已填写的无效引用。
- Playwright 验证页面加载、画面与评分项的同卡关联、1–5 选择、漏填提示、可选引用、完成度更新、JSON 预览和复制操作。
- 重新运行 R-009A 测试、Source Pack stability、Corpus、No-Oracle 和 Candidate preservation 门禁。

## 明确不做

- 不预填或推断 Nick 的评分与理由。
- 不自动提交 Human Score。
- 不执行 `submit-correction` 或 `accept-artifacts`。
- 不修改已冻结的 Build 2、候选包、CraftsOS 或 Layoutcrafts。
